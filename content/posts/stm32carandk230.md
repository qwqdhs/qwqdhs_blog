## 四、第一步：让 K230 认出颜色

### 4.1 为什么用 LAB 而不是 RGB

RGB 三个通道都受亮度影响，光照一变阈值就失效。LAB 里的 **L 是亮度、A 是红绿轴、B 是黄蓝轴**，
把颜色和明暗解耦，白天晚上都能用同一组阈值。

### 4.2 阈值定义

```python
# (L_min, L_max, A_min, A_max, B_min, B_max)
THRESHOLDS = [
    (20, 80,  25,  80,  10,  60),   # 红
    (30, 90, -80, -20,  10,  70),   # 绿
    (40, 90, -20,  20,  45,  90),   # 黄
]
```

> 这三个元组必须用 CanMV IDE 的「工具 → 机器视觉 → 阈值编辑器」实测校准，
> 不同灯光下差别很大。**这是整个项目最需要动手调的地方。**

### 4.3 找色块 + 面积判决

```python
def detect(img):
    best, best_area, best_idx = None, 0, None
    for i, th in enumerate(THRESHOLDS):
        blobs = img.find_blobs([th], pixels_threshold=MIN_PIXELS,
                               area_threshold=MIN_AREA, merge=True, margin=10)
        if not blobs:
            continue
        for b in blobs:
            r = b.rect()                 # 用外接矩形面积比 pixels 属性更稳
            area = r[2] * r[3]
            if area > best_area:
                best, best_area, best_idx = b, area, i
    return best_idx, best
```

**核心思想**：三种颜色都去找，谁的最大色块面积最大，就认定当前是哪个灯。
这样即使画面里同时出现多个颜色（比如背景里有红色物体），也能选出最"显眼"的那个。

### 4.4 显示到屏幕（关键坑）

```python
# 必须用物理屏驱动 + 分辨率与摄像头一致
sensor.set_framesize(Sensor.VGA)        # 640x480
Display.init(Display.ST7701, width=640, height=480, to_ide=True)
...
Display.show_image(img)
```

> ⚠️ `Display.VIRT` 是"虚拟屏"，**只在 IDE 里能看到画面**，脱机运行必黑屏。
> 另外图像宽度必须等于屏幕宽度，否则会横向错行，出现"一条条格子"。

## 五、第二步：打通串口

### 5.1 K230 端（重点：`oe=1`）

```python
from machine import UART, FPIOA
fpioa = FPIOA()
fpioa.set_function(9,  FPIOA.UART1_TXD, ie=0, oe=1)   # oe=1 才是输出使能
fpioa.set_function(10, FPIOA.UART1_RXD, ie=1, oe=0)
uart = UART(UART.UART1, 115200)
uart.write(b"B")
```

> ⚠️ 两个坑：
> 1. 这个 4 芯口是 **UART1（io9/io10）**，不是常见例程里的 UART2（io11/io12）。
> 2. `set_function` 不传 `oe=1` 时引脚**不会输出信号**——表现就是"代码没错，但对端一个字节都收不到"。

### 5.2 协议设计

单字节 ASCII，**只在颜色变化时发一次**：

| 字节 | 含义 |
|---|---|
| `F` | 前进 |
| `L` | 慢行 |
| `S` | 停止 |
| `N` | 待机 |
| `B` | 开机提示（响两声） |

> 事件驱动而不是周期发送，链路干净、不会刷屏，也避免了接收端缓冲区溢出。

## 六、第三步：STM32 接收（软件串口）

### 6.1 为什么不用硬件 USART2

实测在 STM32F103 上把 USART2 重映射到 PD5/PD6 后（`AFIO_MAPR` 已确认写入 0x38），
接收始终拿不到数据、状态寄存器只有帧错误。

于是改成**软件串口**：把 PD6 当普通 GPIO 输入，用定时器精确采样解码。

### 6.2 实现要点

```c
/* 1MHz 时间基准: 注意 F1 的 APB1 分频≠1 时定时器时钟 ×2 */
TIM4_PSC = 71;                 /* 72MHz / 72 = 1MHz  →  1 计数 = 1µs */

/* 检测起始位下降沿后，在位中心采样 8 个数据位 */
for (i = 0; i < 8; i++) {
    wait_until(t0, 9 * 3 / 2 + i * 9);      /* 115200: 8.68µs/位, 取 9µs */
    if (*idr & (1U << 6)) b |= (1U << i);
}
wait_until(t0, 9 * 19 / 2);                 /* 停止位中点 */
if (!(*idr & (1U << 6))) return;            /* 停止位为低 = 噪声, 丢弃 */
```

- **位中心采样**：容错最大，±40% 位宽内都能正确判定
- **停止位校验**：把浮空脚上的噪声脉冲过滤掉（否则会解出一堆 `0xFE`）
- 采样在 PWM 周期的等待时间里轮询，不占用额外 CPU

> ⚠️ 最大的坑：`TIM4_PSC = 35` 看起来是 36MHz/36 = 1MHz，但 **F1 在 APB1 分频≠1 时
> 定时器时钟会自动 ×2**，实际是 2MHz，采样全部快一倍——表现就是"起始位测出 16µs 而不是 9µs"。

## 七、第四步：驱动四个电机

### 7.1 引脚（官方分配表）

| 电机 | 位置 | A 相 | B 相 |
|---|---|---|---|
| M1 | 左前 | PC6 | PC7 |
| M2 | 右前 | PC8 | PC9 |
| M3 | 左后 | PE9 | PE11 |
| M4 | 右后 | PE13 | PE14 |

每个电机是 H 桥驱动：一相给 PWM、另一相拉低 → 正转；交换 → 反转。

### 7.2 软件 PWM

不依赖定时器通道映射，直接 GPIO 翻转：

```c
#define PWM_STEPS 20              /* 分辨率: 0~20 */

static void pwm_cycle(void)       /* 一个周期约 2ms (500Hz) */
{
    for (s = 0; s < PWM_STEPS; s++) {
        for (m = 0; m < 4; m++) {
            unsigned int on = (s < duty[m]);
            if (motor_rev[m]) { A_low; B_out(on); }
            else              { B_low; A_out(on); }
        }
        uart_poll();              /* 顺手轮询软件串口 */
        wait_us_polling(100);
    }
}
```

### 7.3 相位补偿（一定要做）

左右电机是**镜像安装**的，同样给正向信号，两侧转向相反。所以需要一张方向表：

```c
/* 哪一轮方向反了, 就把对应位改成 1 */
static const unsigned char motor_rev[4] = { 1, 1, 0, 0 };
```

> 调试技巧：先让四个轮子**依次各转 0.3 秒**（开机自检里就有），
> 逐个确认转向，再填这张表，一次就能对。

### 8.1 驱动

### 8.2 中文字模怎么来

没有字库文件，用 Windows GDI 把字渲染出来导出成点阵：

## 九、第六步：读电池电压

官方文档明确：**电池采样是 ADC3_IN5 → PF7**（不是 ADC1 的 PA 口），
分压网络 R3=10K / R7=3.3K。

```c
ADC3_CR2 = ADON | EXTTRIG | (7 << EXTSEL);   /* 软件触发必须设这三个 */
... 校准 ...
ADC3_SQR3 = 5;                                /* 通道 5 */
/* 每次读: 置 SWSTART, 等 EOC, 读 DR */

mv = adc * 3300 / 4096;          /* 引脚电压 */
vbat = mv * 133 / 33;            /* 10K/3.3K 分压 ≈ ×4.03 */
```

> ⚠️ 只用 `ADON` 或只置 `SWSTART` 都可能不触发转换，必须
> **EXTSEL=111 + EXTTRIG=1**，这才是标准库 `ADC_SoftwareStartConv` 的真实行为。

## 十、踩坑合集（按严重程度）

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| 1 | 启动文件缺 `.type %function` | 程序完全不跑，灯不闪 | `Reset_Handler` 必须声明为 function，否则向量表存偶数地址 → HardFault |
| 2 | K230 `set_function` 没给 `oe=1` | 代码不报错，对端收不到任何数据 | 显式 `ie=0, oe=1` |
| 3 | K230 4 芯口是 UART1(io9/10) | 用 io11/12 无输出 | 按官方口定义 |
| 4 | F1 定时器时钟 ×2 | 采样快一倍，解码全乱 | APB1≠1 时 TIMxCLK = APB1×2，`PSC=71` 才是 1MHz |
| 5 | `Display.VIRT` | 脱机运行屏幕全黑 | 用 `Display.ST7701` 物理面板驱动 |
| 6 | 图像与屏幕宽度不一致 | 画面变成一条条格子 | 摄像头分辨率 = 屏幕分辨率 |
| 7 | 电池在 ADC3_IN5/PF7 | ADC1 扫遍所有通道都是 0 | 按官方文档换 ADC3 |
| 8 | 软件 PWM 相位 | 有的轮子倒转 | `motor_rev` 按轮子翻转 |
| 9 | 蜂鸣器极性 | 该响时静音、结束后长鸣 | 按实测翻转，并在状态机结束时强制静音 |
